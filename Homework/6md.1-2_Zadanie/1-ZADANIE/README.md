# Бенчмарк производительности: `x in list` vs `x in set`

Сравнение скорости поиска элемента в списке (`list`) и множестве (`set`) на Python с замером времени выполнения и визуализацией результатов.

## Описание задачи
Необходимо замерить среднее время одной проверки вхождения элемента (`target = -1`, худший случай отсутствия элемента в коллекции) для размеров данных $n = 100, 1000, 10000$ и наглядно показать разницу асимптотической сложности $O(n)$ и $O(1)$.

## Что сделано
1. **Подготовка тестовых данных:** для каждого значения $n$ сгенерированы `data_list = list(range(n))` и `data_set = set(range(n))`.
2. **Точный замер времени (`timeit`):**
   - Использована функция `timeit.repeat` с передачей тестовых структур через словарь `globals`.
   - Выполнено 5 серий по 1000 итераций (`number=1000, repeat=5`).
   - Для защиты от случайных выбросов CPU взят минимальный результат (`min`), после чего время нормировано на одну проверку и переведено в микросекунды (мкс).
3. **Анализ ускорения:** в консоли для каждого $n$ выведено время работы обоих подходов и коэффициент ускорения `set` относительно `list`.
4. **Визуализация (`matplotlib`):** построен график в объектном стиле (`fig, ax = plt.subplots()`) с логарифмической шкалой по оси Y (`ax.set_yscale("log")`) и вспомогательной сеткой.

## Результаты экспериментов

| Размер коллекции ($n$) | `x in list` (мкс) | `x in set` (мкс) | `set` быстрее в |
| :--- | :---: | :---: | :---: |
| **100** | ~0.88 | ~0.04 | **~22.7 раза** |
| **1 000** | ~10.46 | ~0.03 | **~309.5 раз** |
| **10 000** | ~108.12 | ~0.03 | **~3194.5 раз** |

## Выводы
- **Список (`list`)** выполняет последовательный перебор элементов — время поиска растёт линейно ($O(n)$) пропорционально размеру коллекции.
- **Множество (`set`)** использует хеш-таблицу — время поиска остаётся константным ($O(1)$) и практически не зависит от объёма данных.
- При частых проверках наличия элементов в больших коллекциях использование `set` даёт выигрыш в производительности на несколько порядков.
